# Codex 引き継ぎ

実装依頼の作業コンテキストとして、このファイルを使用します。

## プロジェクト概要

JSON からカラートークンをインポートすることに特化した Framer プラグインを作る。

## Core 原則

ソース作成者が定義した構造と意図を壊さない。

これは次のことを意味します:
- プリミティブを自動生成しない
- セマンティックを自動生成しない
- スケールを勝手に作らない
- Framer の制約上必要な場合を除き、暗黙に構造を組み替えない
- 未対応ケースや不可逆なケースを明確に表示する

## 直近の優先事項

最優先は、個人利用向けの JSON カラートークンインポートです。

まずインポート経路に集中します。エクスポートや編集はまだ実装しません。

## 現在のスコープ

対象:
- JSON アップロード / 貼り付け
- カラートークン解析
- プリミティブとセマンティック対応
- エイリアスを考慮した処理
- 適用前プレビュー
- 競合処理
- インポートサマリー

対象外:
- Figma 連携
- トークン編集
- トークンエクスポート
- spacing / typography / radius / shadow 対応
- 初回ビルドでの監査実装

## 実装に向けた想定成果物
1. プラグインのスキャフォールド
2. パーサーモジュール
3. サンプルフィクスチャ
4. プレビュー UI
5. インポート適用フロー
6. 競合処理
7. ドキュメント

## アーキテクチャ方針
モジュールは小さく明示的に保つ。
巧妙な抽象化よりも、予測可能な変換を優先する。
可能な限り、ソースパスのメタデータを内部で保持する。

## Codex への推奨プロンプト

JSON からカラートークンをインポートする Framer プラグインの初回実装を作ってください。

要件:
- ローカル JSON アップロードと JSON 貼り付けに対応する
- プリミティブおよびセマンティックカラートークンを解析する
- エイリアス参照を検出する
- インポート前にプレビューを表示する
- スキップ / 置換による競合処理を行う
- 不足トークンを生成しない
- ソース階層と意図をできる限り保持する
- 実装をモジュール化し、ドキュメントを残す

技術検証と、最小限だが実行可能なバージョンから始めてください。
