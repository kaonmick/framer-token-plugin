# Framer プラグイン登録 / リリースフロー

注: これは実務用の作業チェックリストであり、法的文書や最終的なプラットフォームポリシー文書ではありません。

## A. ローカル開発
- プラグインのスキャフォールドを作成する
- 現在のツールで対応している場合、Framer プラグイン開発モードでローカル実行する
- サンプルインポート用フィクスチャを作成する
- 個人用トークン JSON でインポートワークフローを検証する

## B. 内部テスト
- プリミティブのみの JSON をテストする
- セマンティックエイリアス JSON をテストする
- 不正な JSON をテストする
- 競合する名前をテストする
- 大量のトークンセットをテストする
- プレビュー / 適用結果を確認する

## C. ドキュメント
- README を書く
- 利用手順を書く
- プロダクト原則とポジショニング文を準備する
- サンプルスクリーンショット / GIF を準備する

## D. パッケージング
- プラグインメタデータを整える
- アイコン / アセットを確認する
- 命名を確認する
- カテゴリ / タグを確認する
- サポート連絡先とドキュメントリンクを準備する

## E. マーケットプレイス申請
- プラグイン掲載情報を提出する
- プロダクト説明を提供する
- ビジュアルを提供する
- 対応 / 該当する場合は価格を提供する
- レビュー指摘があれば対応する

## F. ローンチ後
- ユーザーフィードバックを追跡する
- 監査機能のロールアウトを優先順位付けする
- 必要に応じて Pro 差別化を準備する

## 直近の推奨アプローチ
マーケットプレイス申請に時間がかかる見込みであれば、次から始めます:
1. ローカル / 個人利用向けの動作版
2. 整ったドキュメントとプロダクトポジショニング
3. 仕上げを速くするための再利用可能なテンプレート / ボイラープレート
