# コア要件とフェーズ計画

## コア要件定義

### 機能要件

#### FR-1 入力
プラグインは以下を受け付ける必要があります:
- アップロードされた JSON ファイル
- 貼り付けられた JSON 文字列

#### FR-2 解析
プラグインは以下を行う必要があります:
- 有効な JSON を解析する
- 無効な JSON を明確なエラー状態で拒否する
- カラートークン構造を検出する

#### FR-3 分類
プラグインはトークンを以下に分類するべきです:
- プリミティブ
- セマンティック
- エイリアスベースのセマンティック
- 存在する場合はモード / テーマグループ

#### FR-4 プレビュー
プラグインはインポート前にプレビューを表示する必要があります:
- 検出されたトークン
- パス
- サンプル値
- 利用可能な場合はエイリアス関係

#### FR-5 競合処理
プラグインは既存の出力先名との競合を検出し、以下を選べるようにするべきです:
- スキップ
- 置換
- 新規項目のみインポート

#### FR-6 適用
プラグインは Framer 内で利用可能なカラートークン表現を作成する必要があります。

#### FR-7 レポート
プラグインは以下を表示する必要があります:
- インポート数
- スキップ数
- 失敗数
- 警告

### 非機能要件

#### NFR-1 予測可能性
出力は安定しており、理解しやすいものであるべきです。

#### NFR-2 忠実性
Framer に合わせるために絶対に必要な場合を除き、構造を変更しない。

#### NFR-3 透明性
不可逆な変換や未対応パターンはすべてユーザーに明示する必要があります。

#### NFR-4 シンプルさ
MVP は軽量で、カラーインポートだけに集中していると感じられるべきです。

## フェーズ計画

### フェーズ 0 — 技術検証
目的:
- Framer プラグイン API とデータモデル上の制約を確認する
- インポートされたカラートークンの最適な表現方法を決める
- ローカルインポートワークフローを検証する

成果物:
- プラグインのスキャフォールド
- サンプル JSON フィクスチャ
- インポートパーサーのスパイク
- 実現可能性メモ

### フェーズ 1 — 基本インポート
目的:
- JSON から単純なプリミティブカラートークンをインポートする

成果物:
- JSON 入力 UI
- パーサー
- シンプルなプレビュー
- プリミティブトークンのインポート

### フェーズ 2 — セマンティックとエイリアス対応
目的:
- セマンティックカラーとトークン参照に対応する

成果物:
- エイリアス解決ロジック
- セマンティック分類
- 参照関係を含む改善されたプレビュー
- 競合処理

### フェーズ 3 — 仕上げと安全性
目的:
- 個人利用で繰り返し使える程度にインポートを信頼できるものにする

成果物:
- より明確なエラー
- 未対応ケースの警告
- より良いサマリー
- フィクスチャベースの回帰テスト

## コアの対象外
- 編集
- エクスポート
- カラー以外のトークン
- 監査ダッシュボード
- 同期エンジン
