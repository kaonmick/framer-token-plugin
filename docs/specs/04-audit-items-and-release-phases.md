# 監査項目とリリースフェーズ

## 監査の目的

監査は、インポートされたカラートークンが Framer 内で正しく使われているか、またトークン運用の規律がどこで崩れているかをユーザーが理解できるようにするためのものです。

## 監査項目

### A1. 未使用スタイル検出
定義:
- どこからも参照されていないインポート済みカラースタイル / トークンを見つける

価値:
- 古くなったインポートの整理に役立つ
- 使われていないデザインシステム資産を特定できる

推奨リリース:
- フェーズ 4

優先度:
- 高

### A2. 直接指定されたカラー使用の検出
定義:
- インポート済みトークン / スタイルを使わず、RAW のカラー値が直接適用されている箇所を検出する

価値:
- トークンガバナンスが崩れている箇所を明らかにする
- 最も実用的な監査価値を提供する

推奨リリース:
- フェーズ 4

優先度:
- 最高

### A3. プリミティブ誤用検出
定義:
- セマンティックトークンを優先すべき箇所で、プリミティブトークンが直接使われているケースを検出する

価値:
- デザインシステムの規律を強化する
- 将来のテーマ柔軟性を保持する

推奨リリース:
- フェーズ 4 または 5

優先度:
- 高

### A4. 重複カラー検出
定義:
- 複数のトークン名が同一のカラー値に解決されるケースを見つける

価値:
- トークン設計の簡素化に役立つ
- 命名の冗長性を表面化する

推奨リリース:
- フェーズ 5

優先度:
- 中

### A5. 命名一貫性の監査
定義:
- 期待される命名規則やパス構造に違反しているトークンを検出する

価値:
- 保守性を支える
- インポートされたシステムの読みやすさを改善する

推奨リリース:
- フェーズ 5

優先度:
- 中

### A6. テーマ網羅性の監査
定義:
- ダーク / ライトの対応漏れや、不完全なテーマセットを検出する

価値:
- テーマ対応システムに有用
- 不完全な実装を避けるのに役立つ

推奨リリース:
- フェーズ 5

優先度:
- 中

## 推奨する監査ロールアウト

### 最初の監査リリース
- 直接指定されたカラー使用の検出
- 未使用スタイル検出

### 2 回目の監査リリース
- プリミティブ誤用検出

### 3 回目の監査リリース
- 重複カラー
- 命名一貫性
- テーマ網羅性

## このロールアウトにする理由

最初のリリースでは、次のような課題に集中するべきです:
- 説明しやすい
- すぐに対応できる
- ユーザーにとって見えやすい
- 有料差別化を正当化できるだけの強さがある
