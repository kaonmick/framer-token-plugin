# MVP 仕様（コアのみ）

## MVP の目的

元のトークン構造と意図を保持しながら、ユーザーが JSON から Framer へカラートークンをできるだけ少ない手間でインポートできるようにする。

## MVP で扱わないこと

以下は含めません:
- トークン編集
- トークンエクスポート
- トークンの自動生成
- Spacing 対応
- Typography 対応
- Radius / Shadow 対応
- 高度な監査
- Figma 連携
- 双方向同期

## 対象ユーザー

すでに JSON 形式のカラートークンを持っており、個人またはチーム利用のために Framer へ取り込みたいデザイナー / 開発者。

## 主要ユーザーストーリー

ユーザーとして、既存の JSON カラートークンを Framer にインポートし、手作業でスタイルを再作成することなく、確立済みのデザイントークンソースを使いたい。

## 対応する入力範囲

MVP では以下に対応するべきです:
- ローカル JSON ファイルのアップロード
- JSON テキストの貼り付け
- プリミティブカラートークン
- セマンティックカラートークン
- トークン間のエイリアス参照
- ソース構造にライト / ダークやテーマグループが含まれる場合の任意のモードグルーピング

## コアワークフロー

1. ユーザーがプラグインを開く
2. ユーザーが JSON をアップロードする、または JSON を貼り付ける
3. プラグインが JSON を解析する
4. プラグインがカラー関連のトークングループを検出する
5. プラグインがインポートプレビューを表示する
6. プラグインが競合と未対応値を強調表示する
7. ユーザーがインポートを確定する
8. プラグインが Framer 内にカラースタイル / 変数を作成またはマッピングする
9. プラグインが結果サマリーを表示する

## 成功基準

- ユーザーが有効な JSON トークンソースを手作業で再作成せずにインポートできる
- ソース階層が予測可能な形で表現される
- プラグインが不足トークンを勝手に生成しない
- エイリアスベースのセマンティックカラーが理解しやすい状態を保つ
- インポート失敗の理由が明確に説明される

## MVP UI 案

### 画面 1: インポート
- JSON ファイルをアップロード
- JSON を貼り付け
- JSON をバリデーション
- 解析エラーを表示

### 画面 2: プレビュー
- 検出されたトークングループ
- プリミティブトークン数
- セマンティックトークン数
- エイリアス数
- 未対応項目数
- 命名 / パスマッピングのプレビュー

### 画面 3: 適用
- すべて作成
- 競合をスキップ
- 競合を置換
- インポートサマリーを表示

## インポート挙動の原則

- ソースパスをできる限り保持する
- 変換が発生する場合は明示する
- 不足しているトークンレイヤーを暗黙に作らない
- セマンティックな意味を暗黙にフラット化しない
- ソース構造をきれいに表現できない場合は警告する
