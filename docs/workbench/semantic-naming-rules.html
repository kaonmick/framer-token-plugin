Semantic Naming Rules

Figma で token を組み直す前提で、Framer Token Importer 用の semantic 命名規則を整理した作業台です。 目的は「色名ではなく役割名で語る」「global semantic と component alias を分ける」「dot 階層を lower-case で統一する」の3つです。

01 / Rules

必須ルール

まずここだけ守れば、Figma と code の両方で命名の揺れがかなり減ります。

1. semantic は役割で命名する

Do: text.primary feedback.warning.surface
Don't: yellow.main gray.700.text

2. 区切りは dot、語は lower-case

Do: feedback.warning.surface
Don't: status.warningSurface warning_surface

3. state は最後に置く

Do: action.primary.hover selection.background.selected
Don't: primaryHover selectedBackground

4. global と component alias を分ける

app 全体で共有する semantic は global。特定 UI 専用のものは component alias に切り分けます。

5. vague な語を避ける

accent ghost は意味が広すぎます。selection.background や feedback.warning.surface のように言い切ります。

6. component 名は最後の手段

本当に再利用先がその feature だけなら component alias に閉じ込めます。global token に preview.* を増やしすぎない方針です。

02 / Grammar

命名の型

基本形は4階層まで。必要最小限で止め、state は必ず最後に置きます。

<domain>.<role>[.<variant>][.<state>]
segment 意味 例
domain 責務の大分類 surface text border action feedback selection syntax
role その domain 内での主役割 primary secondary warning canvas background
variant 用途差分や material surface text accent underline
state interaction / UI state hover pressed disabled focus selected
03 / Domains

推奨 domain セット

global semantic layer はこの範囲に絞るのがよさそうです。component 専用色は別 alias layer に逃がします。

surface

面の階層。app shell, panel, raised, inset を表現。

surface.canvas surface.panel surface.raised surface.inset surface.muted

text

本文と補助ラベル。on-accent や disabled は text にぶら下げる。

text.primary text.secondary text.muted text.on-accent text.disabled

border

境界と focus。太さではなく意味で命名。

border.default border.muted border.strong border.focus

action

CTA や active control。今の accent.* をここに寄せる案。

action.primary action.primary.hover action.primary.disabled action.primary.text

feedback

warning / error / success などの severity。旧 status.* より意味が明確。

feedback.warning.text feedback.warning.surface feedback.error.text feedback.success.accent

selection

checked / selected / highlighted。warning と混ぜない。

selection.background selection.border selection.control selection.background.selected

syntax

JsonTokenEditor などコード表現専用。

syntax.key syntax.string syntax.number syntax.boolean syntax.diagnostic.underline

component alias

feature 専用なら global に入れず、component alias layer へ。

token-card.conflict.accent token-list.new.accent import-summary.warning.badge

05 / Figma

Figma での持ち方

1つの semantic set に全部詰め込まず、layer を分ける前提で考えると整理しやすいです。

Layer 1: primitives

純粋な色階調。色名と数値はここだけに置く。

color.yellow.300 color.neutral.700 color.green.700

Layer 2: global semantics

app 全体で共有する役割 token。

surface.panel text.secondary feedback.warning.surface syntax.string

Layer 3: component aliases

feature 専用で global に上げたくないものだけ。

token-card.selection.background token-list.conflict.accent

Code 変換

Figma の canonical 名から code 側の CSS var / utility を機械的に作る。

surface.panel → --surface-panel → bg-surface-panel feedback.warning.surface → --feedback-warning-surface
この repo 向けの暫定結論

今回の整理では、global semantic は surface text border action feedback selection syntax に絞るのがよさそうです。 特に status.warningGhost のような「名前は warning だが実体は selection」のズレは、Figma 組み直しのタイミングで解消したいです。
